# ferrosa-jepsen — Failure Modes and Effects Analysis

| Failure mode | Effect | Detection | Mitigation / current control |
|---|---|---|---|
| T3 has no live CQL contact points | A multi-DC test could appear to run against `MockCqlSession`. | `Tier::MultiDc` returns an error before the combination starts. | Require exactly the topology's count of `FERROSA_TEST_CLUSTER_NODES`; do not provision a mock fallback for T3/T4. |
| Port-mapped nodes advertise their container port | The Scylla driver discovers addresses it cannot dial and loses its pool. | Real T3 bank setup fails while creating the keyspace. | Each T3 node sets `FERROSA_CQL_BROADCAST` to its distinct host-mapped port; `t3_topology` guards all six mappings. |
| Driver selects a coordinator from a discarded probe session | The workload session's metadata may not contain that host ID, so its single-target policy returns an empty plan and setup fails before operations begin. | Setup reports `Load balancing policy returned an empty plan`; unit regressions require selection from destination metadata and loud failure for an empty node set. | Build one workload session with the normal policy, select a deterministic host ID from that session's metadata, then remap the same session's execution profile to the single-target policy. |
| Topology-aware CQL preflight answers through the wrong T3 process | A client pointed at six contact endpoints can load-balance `system.local` queries onto fewer peers, falsely reporting duplicate/missing nodes; independently random empty-schema UUIDs can falsely report disagreement before DDL. | Workflow contract rejects `cqlsh` topology validation, pins all six CQL/HTTP port pairs, and requires the native-protocol handshake. | Require `OPTIONS` → `SUPPORTED` directly on every CQL socket. Poll `/health` and `/api/cluster/status` directly on every process, require its configured host ID and cluster mode, then require `/api/cluster/ring` on every process to show exactly its DC's three `Normal` members. Let workload DDL exercise schema agreement. |
| Live-infrastructure tests enter the default test target | Plain `cargo test` fails because an intentionally loud missing-infrastructure assertion runs without opt-in. | `live_infra_contract` enumerates live-only targets and individual tests. | Gate them with the `live-infra-tests` feature while preserving panic-on-missing-infrastructure after opt-in. |
| WAN nemesis is selected but never executed | A report labels a faulted run that only tested normal workload behavior. | Orchestrator unit test records inject/heal calls; real runs fail on missing executor. | Run the selected non-`noop` action concurrently with workload and propagate injection/heal failures. |
| WAN command lacks network privilege, tools, or the right IP family | `dc-partition`/`dc-slow` fail instead of changing connectivity. | Command exit status is included in the run failure; the Fly validation applies and removes IPv6 partition and `tc` rules on a real machine. | T3 image installs `iptables` and `iproute2`; all six T3 services declare `NET_ADMIN`; topology test guards capability; WAN partition selects `ip6tables` for Fly private IPv6 addresses. |
| Stale Docker CLI masks a functioning Podman daemon | Local fault executor targets an unavailable Docker service. | Runtime selection fails or commands cannot start. | `container_runtime()` checks `info` and chooses a usable daemon; `FERROSA_CONTAINER_RUNTIME` can explicitly select one. |
| Local Apple Podman emulates AMD64 netfilter incompletely | `iptables`/`tc` cannot exercise a Linux WAN fault locally. | The command fails loudly with its kernel error. | Treat this as an unsupported local fault host; validate the compose path on native Linux CI or Fly, never turn the nemesis into a no-op. |
| A refused serialization attempt is recorded as the operation's result | A register read/modify/write or predicate read the engine refused is recorded as if it had applied; most of those invocations are silently abandoned and the run still "passes". | The history-length identity (`expected_history_length`) would not reconcile if a refused attempt were counted as a completion; the register/predicate retry counters stay at their floor while the transfer counter moves. | Route EVERY operation kind through one retry policy (`retry_serializable_transactions`) and record every attempt, refusals included; reconcile the history length against the per-kind retry counts (`OperationRetryCounts`). |
| A serialization retry re-enters in the same instant as the attempt that lost | Because a refusal changes no state, the retry re-reads exactly what lost and re-enters the same conflict window, so it loses until the budget is spent — the workload's progress assertion fails without the engine being wrong. | The retry budget (`SERIALIZATION_RETRIES`) is consumed with no commit; measured 13, 7 and 7 consecutive refusals in three runs against a usual one. | Pace the retry: bounded exponential backoff (10 ms base, 160 ms max, five-step cap) with jitter from the refused attempt's OWN invocation sequence, so it lands in a different conflict window. This bounds WHEN a retry is issued, never how many. |
| A refusal whose outcome is unknown is re-issued | A statement that may already have applied could be applied twice. | n/a — the workload never re-issues this class. | Retry only the class the server documents as "not applied": SQLSTATE `40001` for a transaction, `Unavailable`/0x1000 for the teardown DDL. A `RequestTimeout` outcome is unknown and is reported where it stands. |
| A DDL proposal with a stuck leader hangs the teardown to the driver's 30 s deadline | The teardown reports `ExecutionError::RequestTimeout(30s)` — a failure the workload cannot retry, because its outcome is unknown. | Engine log: `ddl_path: ddl_agreement: timed out waiting for all voters to replicate the DDL log entry … lagging_voters=1`. | `ferrosa-cluster` bounds the DDL proposal to the existing 5 s agreement budget and returns the retryable class, which the driver's default retry policy re-issues unconditionally. No deadline is widened, and the teardown's own re-issue is limited to the not-applied class. |
| A checker the workload requires does not run | The run is judged by the remaining checks, which a transactional workload passes vacuously, so a history nothing judged reads green. | `a_required_checker_that_did_not_run_fails_the_run`, `an_absent_required_checker_must_fail_the_run` (mirrors Lean `Jepsen.an_absent_required_checker_must_fail_the_run`). | `AllCheckResults::all_passed` passes an absent result only for an optional checker; the orchestrator records a `setup_error` naming the checker. |
| A setup failure is counted as "not tested" | Setup failures carry the default `NotTested` assurance, so the report counted them as untested and the suite exited 0 on a run that decided nothing. | `a_setup_failure_fails_the_run_rather_than_going_untested`. | `CombinationResult::is_inconclusive` is false for a setup failure, so `RunReport` counts it as failed. |
| The Elle verdict is read from the checker's text | A nested `:valid? true` inside an invalid result passes the history, and a lower-cased anomaly search names nothing (Lean `Jepsen.a_scraped_verdict_passes_an_invalid_result`, `a_lower_cased_anomaly_search_finds_nothing`). | `a_nested_valid_true_in_the_output_does_not_pass_an_invalid_exit`, `elle_verdict_comes_from_the_exit_code`, `anomaly_names_keep_elles_upper_case_spelling`. | The verdict is the exit code; anomaly names are the top-level keys of the anomalies file; stdout is never parsed. |
| The Elle checker runs but reaches no verdict | An exit other than 0/1, a missing anomalies file, or a stale one from an earlier run could be read as a verdict. | `an_exit_other_than_zero_or_one_is_a_checker_error`, `a_missing_anomalies_file_is_a_checker_error`, `a_required_checker_that_could_not_run_is_a_setup_failure`. | Each is an `Err`, which the orchestrator records as a `setup_error`; a stale anomalies file is deleted before the checker runs. |
| A loss and a fabrication cancel in one error count | A run that lost one acknowledged value and returned one value no write produced reports a balanced count and passes. | `checker::book` tests mirror `Histories.lean` (`a_loss_and_a_fabrication_do_not_cancel`); `set` test `a_loss_and_a_fabrication_are_reported_separately`. | The book keeps four multisets; `lost` and `fabricated` are derived and reported separately, and either one refutes. They are never summed. |
| A timed-out write that landed is called a fabrication, or a definite refusal that landed is excused | The first is a false red; the second hides a value the database said it never wrote. | `set` tests `a_timed_out_write_that_landed_is_not_fabricated` and `only_a_not_applied_refusal_is_definite`. | Only errors the protocol defines as not applied (or driver errors raised before sending) are definite; every other error, and any unrecognised one, is indeterminate, which can excuse a recovered value but never a loss. |
| The final read fails or is skipped | Every acknowledged write would count as lost — red for the wrong reason — or the run would be judged with no read at all. | `set` test `an_unreadable_bucket_is_a_run_failure_not_a_verdict`; orchestrator test `the_set_workload_is_judged_by_its_final_read`. | The orchestrator calls `Workload::final_read` after the nemesis heals; a bucket still unreadable after `FINAL_READ_RETRIES` logged retries fails the combination as `setup_error` "final read failed: bucket N". |
| The final read materialises a whole bucket | A long run's bucket held in memory at once. | `scripts/check-unbounded-reads.py` and the OOM audit. | Clustering-range pages of `FINAL_READ_PAGE` rows; a page that overfills, goes backwards or leaves the run's value range is refused, so paging cannot loop or double-count. |
| A write-free run is reported green | A durability claim from a run that could not lose anything. | `set` test `a_run_without_acknowledged_writes_is_not_tested`. | No acknowledged write turns a clean book into `NotTested("no acknowledged writes")`; a fabrication still refutes. |
| A Fly partition targets loopback because the client dials through `fly proxy` | The DROP rules match nothing, the cluster never partitions, and the run reads as a clean faulted run. | `a_fly_nemesis_aimed_at_loopback_is_refused_rather_than_partitioning_nothing`, `a_malformed_fly_node_ip_override_is_refused_naming_the_variable`. | `FERROSA_JEPSEN_FLY_NODE_IPS` supplies the machines' private addresses, parsed `from_vars`-style: every entry must be an IP address, and a malformed value, a count mismatch or a loopback target fails the run before it starts, naming the variable. |
| A partition rule that never applied, or never lifted | The run is labelled partitioned while the cluster was whole, or the next combination starts partitioned. | `verify_rules` re-checks every appended rule with `-C` on its node: present after inject, absent after heal, else the nemesis fails. Each command and its exit code is logged. | Netfilter family chosen per peer address; checks print a marker so they exit 0 and a transport failure stays distinct from an absent rule. |
| A process kill that did not bite | A kill nemesis that killed nothing (wrong process pattern, a no-op transport) labels a fault-free run as a crash run. | On Fly the inject logs the ferrosa PID and age, then polls the machine's state in `fly machine list --json` until `stopped` and fails otherwise; after heal the ferrosa process must be younger than the heal (a PID can repeat in a freshly booted machine, an age cannot), else the heal fails naming the node. The container transport refuses kill-minority outright. | SIGKILL stop through the Machines API rather than an in-guest `pkill`, whose `-f ferrosa` would also match its own shell. |
| A killed node never rejoins | The rest of the run is a smaller cluster, a weaker test reported as the requested one. | `wait_until_serving` polls `/readyz` for 300 s and fails the heal; transport errors while booting are logged once per outage edge. | Heal is an error, so the combination is recorded as a failure, not a pass. |
| The driver retries a write whose first attempt landed, then reports a definite refusal | The landed value would be classified as a fabrication — a false red. | Not detected by a unit test; a fabricated value in a live run must be checked against the coordinator log before it is reported as a defect. | The set INSERT is sent as an unprepared, non-idempotent `Statement`, and scylla 1.6's `DefaultRetryPolicy` re-sends a non-idempotent request only after `Unavailable`, `IsBootstrapping` or a stream-id allocation failure — all not-applied — so a definite final error implies every earlier attempt was refused too. Marking the statement idempotent, or changing the retry policy, would break this and must reclassify. |

The controls above deliberately prefer a loud, diagnosable failure to a
successful-looking test that did not use its requested topology or fault.
